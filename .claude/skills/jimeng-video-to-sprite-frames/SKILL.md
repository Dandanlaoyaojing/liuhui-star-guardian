# 即梦视频 → 游戏精灵帧动画管线

## 问题

要把一张角色定妆图(如莱米 canonical)做成游戏里能循环播放的 2D 逐帧动画(走路/待机/够东西)。
直接用 AI 反复生图会身份漂移;纯引擎变换像橡皮膜;手绘成本高。
**有效路线:用即梦图生视频生成一段动作,再抽帧做成精灵帧。** 但这条路有一堆坑,
本 skill 是踩平后的成品管线。

## 触发条件

- 有一张干净(最好透明)的角色定妆图,想做帧动画
- 出现这些症状之一:角色"越走越大"、脸/比例变形、纯侧脸多出第二只眼、颜色发灰掉色、帧数少导致卡顿
- 需要把 AI 生成的 mp4 转成可进引擎的透明精灵帧

## 前置

- 即梦 CLI `dreamina` 已装(`~/.local/bin/dreamina`),已 OAuth 登录(`dreamina user_credit` 能查余额)
- `ffmpeg` 已装
- 一张角色定妆图(透明 PNG 最佳);若背景是棋盘格/纯色,先用连通域 flood-fill 从四角抠透明(只抠和边缘连通的背景,避免抠掉角色身上浅色造成内部破洞)

## 解决步骤

### 1. 准备首帧输入图
- 角色图转成**白底 PNG**(视频生成用白底比透明稳,后续好抠):`Image.alpha_composite(白底, 透明图)`
- 记下角色**朝向**(看脸和脚指向哪边)——决定只能朝那个方向走,反向靠镜像翻转

### 2. 用即梦生成动作短视频(防漂移的关键全在这步)

强约束清单(全部写进 prompt 或用对命令):

| 目标 | 做法 |
|---|---|
| 大小不变/不漂 | **优先 `frames2video` 首尾帧都用同一张定妆图** → 首尾强制一致,中间被两端拉回。实测首/中/尾帧身高完全一致(228/228/228) |
| 形象不漂 | prompt **只写动作,绝不写美术细节**("红色/蓝灰色水彩"会把模型带跑,尤其"蓝灰色"把暖灰带成冷色) |
| 镜头不动 | prompt 明确"固定机位、不推拉缩放平移、角色同位置同大小" |
| 纯侧脸不长第二只眼 | prompt 明确"全程纯侧面、头不转动、始终只露一只眼、脸朝向不变" |
| 动作幅度 | 单一动作、幅度小、时长 4-5s → 漂移最小 |
| 队列快 | VIP 账号用 `--model_version=seedance2.0_vip`(queue_idx:0 秒进;普通版排免费33万队列);`--video_resolution=1080p` 仅 vip |

走路/位移类动作:让角色**原地踏步**(不要真走出画面),移动靠引擎位移。待机类:`frames2video` 首尾锁同图最稳。
命令模板见 `scripts/gen-video.sh`。
**注意**:`video_url` 后缀不是 .mp4(带 mime_type 参数),下载要解析 JSON 的 `"video_url"` 字段,别按扩展名 grep。

### 3. ffmpeg 抽独立帧
`ffmpeg -i 视频.mp4 -vf "mpdecimate,setpts=N/FRAME_RATE/TB" -vsync vfr 帧-%03d.png`
mpdecimate 去重复帧(60fps 视频实际独立帧约 100-120)。**帧太少会卡顿:走路抽 24-36 帧,待机 12 帧。**

### 4. 逐帧规范化(治"忽大忽小"+抠透明+校色) —— 核心
对中段稳定区均匀取 N 帧,每帧:
1. **测角色 bbox 身高 → 按各自身高等比缩放到统一 TARGET_H**(必须等比!只压高度会变形)
2. **脚底锁定同一 GROUND 基线**、水平按脚部重心对齐 → 不上下跳不左右跳
3. **白底转 alpha**:接近纯白判透明,边缘羽化
4. **HSV 色彩迁移到 canonical**(均值+方差迁移,保 hue 只校 S/V) → 修掉发灰/掉色

完整实现见 `scripts/extract-frames.py`(改 SOURCE/动作名/帧数即可复用)。
验证:输出每帧身高应完全一致(如全 429px)、四角 alpha=0。

**⚠️ 归一化策略按动作类型分两种(关键):**
- **循环动作(walk/idle):逐帧等高归一化** —— 走路/待机时身高应恒定,任何起伏都是漂移,必须消除。
  - ⚠️ **等高归一化只锁身高,锁不住即梦的"宽度/体积"抖动**。长耳角色走路用 `extract-frames-bodynorm.py`(按不含耳身体高归一)能稳身高,但身子宽度仍摆(实测正面3/4走路**宽度摆 26%**)→ 走路恒定大小时暴露成"忽大忽小"。**解法:再加一步 `area-norm`**——按每帧**整体不透明面积**uniform-scale(均匀缩放、不变形),锁"看起来多大"而非单维度(实测面积摆幅 11.6%→**0.7%**,忽大忽小消失,残留只剩极轻微身形摆动)。管线:抽帧+bodynorm → **area-norm 锁面积** → 收尾。**侧视图比正面3/4稳**(正面转身/摆臂令侧影宽度大起大落,纯侧面侧影恒定;但纯侧面源若在转身,宽度摆反而更大——按实测选,别想当然)。
- **弧线动作(reach 够篮/跳跃/下蹲等):统一缩放系数 + 脚底锁定,保留真实高度起伏** —— 蹲矮→伸高是动作本身,**绝不能等高归一化**否则毁掉踮脚伸展。做法:先扫所有帧求全局最大身高算一个统一 SCALE,所有帧用同一 SCALE 缩放、脚底锁同一基线。
- 帧数:简单/循环 12-48 帧;复杂弧线动作可多抽到 36-48 追顺滑(发行无包体限制时帧数按质量给足)。
- **⚠️ 抽帧+缩放会压低对比度(发平/发闷)**:HSV 色彩迁移在缩放【前】匹配,LANCZOS 降采样后 V 方差被压(实测同口径 canonical `V.std=0.160` → 帧只 `0.143`,肉眼比定妆图平)。要帧与定妆图对比度一致,收尾加一步 **`tone-match`**:把每帧身体 V 线性重映射到 canonical 的 V.std(保各帧自身 V.mean,只提对比、不改亮度/色相/饱和)。**坑:测对比度别排"中性灰"像素**——会连角色身上的灰部件(灰肚子等)一起排掉,把 V.std 测虚低、得出错误结论。

**⚠️⚠️ 保持大小一致·进阶(2026-06-08 莱米"耳后贴"系列实战,核心经验):**
- **跨片对齐的尺寸基准用「躯干宽」,别用「身高」**。不同 clip 即梦渲染的绝对大小/姿势角度有别(同一角色也是);身高(脚→头顶)既被【移动的耳朵/附肢干扰检测】、又随姿势(耳竖/垂、机位正/侧)变。**躯干宽(下半身腹部宽,在耳朵下方)对耳朵姿势/移动免疫**,是最稳的"同一只兔多大"标尺。做法:量参照动作(idle)躯干宽 → 各 clip 用【一个统一缩放系数】把躯干宽对到该值。⚠️身高反例:idle 386 vs 耳后贴 358,按身高对齐会把更正面的姿势放得更宽=更显壮;改按躯干宽对齐才"看起来一样大"。
  - ⚠️**取躯干基准:循环/恒姿动作用中位数(鲁棒);但弧线动作(reach够/crouch蹲/jump跳)必须用【站姿首帧】躯干,不能用中位**——下蹲/伸展帧会把躯干撑宽、抬高中位 → 按中位缩会把"站姿"过缩(实测 crouch 中位140 vs 站姿135,按中位缩到站姿躯干126<idle131,够篮/下蹲完接 idle 反而缩一下)。动作间过渡都发生在站姿,故对齐站姿。修法是在【现有帧】上做一次脚底锚定的均匀缩放(scale=131/站姿躯干),不重抽。
- **耳朵/附肢在动的转换片(收耳/展耳)必须「全程一个统一缩放」,不能逐帧按身高归一**。`bodynorm` 的 `head_top_y`(0.42 宽阈值找头顶)在耳朵扫过检测区时参考点忽上忽下 → 逐帧系数乱跳 → **身体忽大忽小**。耳不动的循环(耳后贴 idle/walk)逐帧归一无妨;**耳在动就改统一缩放**。
- **跳跃动作(脚离地)用「跳跃模式」,别脚底锁地**。foot-lock 每帧把脚钉地=腾空压平。改按【源地面线=全程最低脚底】锚定,脚比它高的帧自然离地、保留蹲地起跳/顶头的腾空。
- **循环动作只抽「一个动作周期」循环复用(省内存 + 节奏对)**。别抽 3-5s 一大段(含多个呼吸/步幅周期→循环时连喘好几口=显快+浪费内存)。用整帧图像差自相关找【相位闭合单周期】(首尾同姿势无缝),只在这段抽;**周期内尽量多抽**(密集→慢放也顺)。回放快慢 = 帧数/fps(密集抽完只调 fps,不重抽)。匹配参照节奏:设 fps 让单周期播放时长 = 参照的呼吸/步幅周期。
- **要"圈内多抽"必须绕开 mpdecimate**。bodynorm/arc 内部 `mpdecimate` 删相邻近似帧(60fps 细微运动被删大半)→ 慢放不顺。用**目录模式**:自己 `ffmpeg -ss A -to B -vf fps=NN` 从源密集抽好,把【帧目录】当第一参数喂进去(不去重)。
- **固定机位生成的视频大小本就稳**(用户经验):机位锁死、不推拉缩放 → 同一 clip 内身体恒定,不需为治漂移逐帧归一;跨 clip 不一致用上面的统一缩放(一个系数)对齐即可,逐帧归一反而引入抖动。
- **`extract-frames-bodynorm.py` 参数(本次扩展后)**:`<视频|帧目录> <canonical> <出目录> <动作> [N] [seg_lo] [seg_hi] [target_body_ratio] [uniform_torso_px] [jump_mode=1]`。帧目录模式忽略 N/seg;给 `uniform_torso_px` 走统一缩放(治耳动抖、跨片对齐);加 `jump_mode=1` 保腾空。

### 5. 按显示尺寸压缩运行时帧(治显存/包体) —— 别存超大帧
抽帧脚本默认输出 512²,但游戏里角色显示往往只有 ~180px,512 是 2.8 倍浪费显存。
**按显示尺寸压缩:显示 180 → 帧 256-384 足够(留 1.4-2 倍余量给高DPI屏),再 pngquant 压。**
- 实测:512²×66帧=8MB → 384²+pngquant=1.9MB(降76%),运行显存同步降~75%,180显示无肉眼差别。
- 命令:`scripts/compress-frames.sh <帧目录> <动作名> [目标尺寸=384]`
- **前提:高清源视频已归档**(见第7节),压小运行时帧是安全的——要高清随时从源视频重抽。
- 缩放后等高归一化的帧会有亚像素 ±1px 抖动(抗锯齿致,肉眼无感,正常)。

### 6. 朝向与移动(游戏侧)
- 角色只能朝定妆图的朝向走;反向用 `scaleX=-1` 镜像翻转,**不要重新生成**
- "走路移动" = 原地踏步循环帧 + 引擎 tween 横向位移(2D 标准做法)

### 7. 归档源视频(可重抽,不可再生)
即梦源视频是动画唯一源头(重新生成要花积分且可能漂移),**放 git 跟踪目录**(如 `assets/.../source-videos/`),
**不要放 temp/**(被 gitignore 会丢)。配 README 记录每个视频对应动作+参数。
以后任何动作要加密(多抽帧),从源视频重抽即可,不用重新生成。

## 注意 / 坑
- **Luma `--modify`(img2img)会累积脏噪点**,别用它做角色微调;要干净图用 text2image 重生
- 即梦长视频(10s+)后段必漂,**拆 3-5s 短视频分动作**
- 即梦 content policy 会误杀正常 prompt(如"举起前爪够东西"被拒),换中性措辞重试
- `frames2video` 首尾同图 → 动作"回到原点"(适合 idle/呼吸/原地循环);要净位移动作首尾用不同姿态图
- 中文文件名在 shell 里是 NFD 编码,grep 匹配不到,用 Python `unicodedata.normalize('NFC',...)` 或按文件大小定位
- **即梦会把 prompt 里写的具体物体真画进画面**(如"小物件落到头顶"→真画一颗果子)。要某物体**不出现**就别在 prompt 提它;若已生成,用"重组抽帧"丢掉只含该物体的帧(物体常只在动作前段出现、中后段已离开),**别硬抠**——水彩抠图+局部 inpaint 极易花。
- **即梦把"吃惊瞪眼"固定画成"大白眼圈+小黑点"**,prompt 明确要求"只微睁、保持深色圆眼珠"也改不动;事后合成虹膜(连通域定位白巩膜→贴 canonical 虹膜)在水彩上难自然、易被否("瞳孔不像/瞪太大")。精确眼神微表情**考虑手绘极少数关键帧**,别指望即梦或自动合成。
- 抽帧脚本三选一:① 循环恒高(idle,耳朵基本不动)→ `extract-frames.py`(逐帧按**含耳总高**等高归一化);② 弧线/大小本就变化(reach/startle/蹲下)→ `extract-frames-arc.py`(统一缩放+脚底锁定+**主簇 bbox** 剔除运动模糊悬空块);③ 长耳角色走路想稳身高 → `extract-frames-bodynorm.py`(按**不含耳的身体高**归一化:长耳走路时耳朵摆动会让"含耳总高"变,等高归一化反而把身子忽大忽小;按身体高归一才稳)。
- **⚠️ 即梦逐帧重画身子"胖瘦/体积"有 ~8–11% 的固有抖动**(实测走路和蹲下都有),等比缩放修不掉(非等比硬拉宽度会变形),重新生成也大概率还抖。判断:**动作本身让不让抖动显形**——大小本该变化的动作(蹲/够/受惊)抖动被掩盖、没问题;但**"大小必须恒定"的走路循环会把它暴露成忽大忽小**。结论(**2026-06-05 更新,有救了**):**两条路**——(A) **area-norm 锁面积**(见第4节归一化策略):对每帧整体不透明面积 uniform-scale 归一,忽大忽小消失(实测面积摆 11.6%→**0.7%**),**保住即梦帧的真实动作**,残留只剩极轻微身形摆动;(B) **引擎变换**(单张 canonical 位移+轻微 squash/起伏)零抖动但无真迈步、像橡皮膜。**要即梦真实帧动作→A;要绝对零抖动且接受橡皮膜→B**。(本项目 2026-06-02 因当时只会"等高归一化"、修不掉宽度抖动而误判"即梦走路不可用"、回退引擎;06-05 用 area-norm 把正面3/4走路救回。教训:别只锁单一维度就下"不可用"结论。)
- `preview-gif.py` 的"雪花"坑:每帧各算 ADAPTIVE 调色板+Floyd-Steinberg 抖动,平涂背景上抖动点逐帧漂移=肉眼雪花(运行帧 PNG 本身没事,只是 GIF 预览)。已修为**全帧共享调色板+`dither=NONE`**。

## ⚠️ pngquant 压缩的安全边界(2026-06-01 实测)
- **pngquant(有损256色量化)对"高对比色块+清晰线稿"安全**(莱米动画帧实测66帧压缩后掏空0、色差<3,肉眼无损)。
- **对"大面积低对比水彩"会视觉掏空**(篮子底深色叠透明:相近色被归并,看起来被抠空)。
- 判断:主体颜色分明/线稿清晰→pngquant可用;大片相近色/低对比水彩→改用 **oxipng/zopflipng 无损重压**(像素零改变)。
- 检测损坏别只看alpha直方图(数据可能没变但视觉坏了),要比对"原本不透明现在变透明的像素数"+"不透明区RGB色差",或肉眼叠棋盘看。
